# 资料库（Library）模块评审与优化建议

> 评审日期：2026-09-11 ｜ 范围：`src/features/learn/**` + `src/ai/retrieval` + `src/storage` + `src/domain|engine`
> 依据：README.zh-CN.md（项目目标与 MVP 成功标准）、`docs/library-module-design-2026-09.md` 系列
> 方法：代码事实核查（区分「已实现并接线」与「只有定义无调用方」）

---

## 0. 一句话结论

**资料库目前是一个完成度很高的「本地知识库」，但还不是一个「学习系统的资料层」。**

资料管理侧（导入 / 切分 / 检索 / 替换 / 追加 / 删除 / 级联）已经相当完备，工程细节（PDF 版面重排、掌握度迁移、混合检索降级、批量失败续算）都做得很扎实；
但**学习侧的关键三跳是断的**：资料 ↔ 学习目标、阅读 ↔ 掌握度、资料 ↔ 测评。

按 README 的 MVP 成功标准（导入一本书 → 生成知识体系 → 学习 → 答题 → 判断掌握 → 发现薄弱 → 推荐下一步），
当前**卡在「学习 → 判断掌握」这一跳**：掌握度只能由试卷写入，阅读不产生任何学习证据，测评页甚至不读资料数据。

> 优化主线应该是：**从「把资料管好」转向「让资料为学习目标服务」**——而不是继续加资料管理能力。

## 1. 已有功能清单

### 1.1 导入（三来源）

| 能力 | 实现 | 约束 | 证据 |
|---|---|---|---|
| 粘贴文本 | ✅ markdown / note / web / txt 四种格式 | **无任何体积护栏** | `import/types.ts:17-30`（无 paste 条目） |
| 本地文件 | ✅ `.md/.markdown/.mdown`、`.pdf` | md ≤1MB、pdf ≤30MB / ≤500 页；`.txt` 被判不支持 | `types.ts:19/21/23/100` |
| GitHub 公开仓库 | ✅ `.md/.markdown/.mdx` | ≤60 文件、单文件 ≤1MB、合并 ≤150 万字符 | `github.ts:158/182/188/229` |
| PDF 版面重排 | ✅ y 聚类成行 → 分栏判定 → 跨页页眉去噪 → 折行修复 → 疑似标题提升 | 纯函数、不依赖 pdfjs、**不做 OCR** | `import/pdf-layout.ts` |
| 编码兜底 | ✅ BOM → 严格 UTF-8 → GB18030 | — | `import/decode.ts` |

### 1.2 组织与管理

| 能力 | 状态 | 备注 |
|---|---|---|
| 资料列表（卡片网格） | ✅ | 名称 / 导入时间 / 类型 / 来源 / 章数 / 掌握度统计 |
| 过滤与排序 | ✅ | 全部 / 未切分 / 进行中；最新 / 最早 / 标题 |
| 资料级操作 | ✅ | 重命名、编辑元信息、替换正文、追加正文、删除、切分、重新切分（均带确认） |
| 删除级联 | ✅ | Chunk+向量 → 试卷 → 概念节点与关系 → 资料本体，顺序固定避免半清理 |
| 导入导出 / 备份 | ❌ | **完全缺失**（local-first 产品的数据主权刚需） |
| 批量操作 | ❌ | 无批量删除 / 打标 / 移动 |
| 学习空间（Spaces） | ❌ | `SpacesPage` 仍是 scaffold 占位 |

### 1.3 切分与索引

| 能力 | 实现 | 关键参数 |
|---|---|---|
| 章节切分 | ✅ 纯代码、零 AI（确定性可复现） | Markdown 标题正则，默认只认 `#`/`##`；降级按空行聚类 1600 字符；短章 <200 字符合并；单章上限 10000 字符 |
| AI 精修切分 | ✅ 可选、失败静默回退 | `refineSplitResult`，仅导入管道与详情页手动触发 |
| Chunk 生成 | ✅ | 目标 400 token、硬上限 512，超长二分 |
| 向量化 | ✅ 本地 `qwen3-embed:0.6b`（1024 维），批 16，不走 AIProvider | 仅桌面端；浏览器预览直接跳过 |
| 自动索引 | ✅ 导入 / 重切 / 替换 / 追加四条路径均触发 | 单批失败折半重试一次，仍失败计入 failed 可续算 |
| 切分参数 UI | ❌ | 全部硬编码，用户无法调 |

### 1.4 检索

| 能力 | 实现 |
|---|---|
| 全文检索 | ✅ SQLite FTS5（trigram） |
| 向量检索 | ✅ 本地 embedding 余弦 |
| 混合融合 | ✅ RRF；无 embedder 时降级为纯全文（页面显式提示 `fulltextOnly`） |
| 元信息过滤 | ✅ 标题 / 来源 / 章标题 / 要点（与正文检索分工明确，且资料列表恒为页面主体） |
| 消费范围 | ⚠️ **仅资料库列表页一处**，无全局搜索入口、无高级筛选（格式 / 时间 / 掌握度） |

### 1.5 详情页与阅读

| Tab / 页 | 能力 | AI 触发 |
|---|---|---|
| 概览 | AI 整篇导读（gist / 脉络 / 关键词 / 读前需知）+ 本地统计 | 手动按钮 |
| 资料内容 | 按 format 分派渲染器、`?at=` 原文锚点高亮、20 万字截断 | — |
| 章节列表 | 切分（代码）+ AI 精修（手动）；章行含状态徽标 / 掌握度条 / 展开预览 | 手动 |
| 关键知识点 | 要点带原文引用（可跳原文）+ 概念图谱 | 手动（两个按钮） |
| 章节试卷 | 列已有卷 + 成绩 + 推荐卷型（只读，无保存） | — |
| 章节阅读页 | 正文渲染、打开即置 learning、标记学完、到期复习排期、Why it matters、知识 chips、Evidence | — |

> 所有 AI 能力均需手动触发且要求 `useAiReady`；**无任何自动触发**——这是正确的设计（避免静默烧 token），但不等于闭环成立。

### 1.6 知识图谱

- 画的是**概念级图**（KnowledgeUnit），非资料级；数据来自 `storage.getGraph()`（localStorage），按 `Chapter.unitIds` 裁剪子图。
- 关系类型含 prerequisite / related / parent / child / example / contrast / application / source，AI 会产出。
- 交互：滚轮缩放、单击聚焦一跳邻域、双击回资料、侧栏关系清单、缺口脉冲。
- ⚠️ 节点是 `<g>`，**无 tabIndex / role → 键盘不可达**。

## 2. 目标对齐度评估

对照 README § 路线图 Phase 1 MVP 与「MVP 成功标准」：

| MVP 要求 | 现状 | 判定 |
|---|---|---|
| 导入 PDF/MD/TXT | 仅 MD / PDF 落地；DOCX/EPUB/网页/图片OCR **零实现**；本地 `.txt` 被拒 | ⚠️ 部分 |
| 文档解析、Chunk、知识提取、来源引用 | ✅ Chunk 落 SQLite；要点带原文引用 | ✅ |
| 知识图谱：知识点 + 父子/前置/相关 + 可视化 | ✅ 有图有交互；但**前置关系不参与章级规划**（只被概念层 buildPlan 用） | ⚠️ 部分 |
| 学习者状态：掌握度/尝试/正确率/最近复习 | ✅ 掌握度引擎与遗忘衰减齐备 | ✅ |
| 测评：自动出题、AI 评估、掌握度更新 | ⚠️ 掌握度**唯一写方是试卷**；`assessment` 页走概念层快照，不读 doc/chapter | ❌ 断裂 |
| 学习规划：差距检测、下一步最优动作 | ⚠️ 章级计划可用，但**资料库侧零 goal 引用** | ❌ 断裂 |
| 多知识库 / 跨库关联（Phase 2） | ❌ Spaces 占位 | ❌ |

**关键事实**：`src/features/learn` 全目录 grep `goal` **零命中**——资料库完全不知道用户「为什么学这些资料」。
这是与产品定位（"Learning Goal 是整个系统的重要入口"）最大的偏离。

## 4. 优化建议与里程碑

### M1 — 让资料服务于目标（解 P0-1 / P0-5 / P2-5）

1. **资料归属维度**：给 `SourceDocument` 增加 `goalIds: string[]`（或先做轻量 `tags`），资料卡与详情页可关联目标；列表页增加「按目标 / 标签」过滤。
2. **目标页反哺**：目标详情页显示「已覆盖资料 N 本 / 覆盖章节 M / 缺口章节 K」，点击直达资料。
3. **资料卡行动化**：卡片增加「继续学习 →」（跳到下一未达标章）与「下次复习」字段，让列表页驱动行动而非只做陈列。
4. **收敛格式宣称**：README 明确标注「当前支持 .md / .pdf，其余格式规划中」，或补齐 `.txt` 本地导入（成本极低，收益立竿见影）。

> 建议先做 3（最小改动、体感最强），再做 1+2（需要动 domain 与 goal 侧）。

### M2 — 补上 Learn→Prove 这一跳（解 P0-2 / P0-3 / P1-1）

5. **出卷入口前置**：资料详情页「章节试卷」Tab 从只读改为可直接出卷（复用 `createPaper`），让"学完这张卷"在资料上下文内完成。
6. **阅读产生证据**：阅读完成 / 标记学完后，写入一条轻量学习事件（时长、次数），作为 Evidence 与置信度校准输入（不直接改掌握度，保持 Evidence-based 原则）。
7. **测评接回资料**：`AssessmentPage` 允许以「某资料的章集合」为作用域生成测评，而不是只走概念层快照。
8. **全局检索入口**：顶部或命令面板级搜索（跨资料正文 + 章 + 要点），结果可跳章、可看出自哪本资料。

### M3 — 让知识图谱真正成为资产（解 P0-4 / P1-3 / P2-1）

9. **概念层落 SQLite**：把 `saveGraph` 的产出同步写入 `knowledge_units` / `knowledge_relations`，并让 `index-service` 的概念向量不再返空。
10. **前置关系参与规划**：让 `prerequisitesOf` 进入章级 `buildPlan`（当前只有概念层用），使"发现基础缺失 → 补救学习"这条 README 承诺的能力真正生效。
11. **回填结构上下文**：`chunk.sectionId` / `knowledgeIds` 至少回填章级锚点与命中要点，让检索结果具备层级面包屑。
12. **图谱 a11y**：节点补 `role="button"` + `tabIndex`，支持键盘遍历与 Enter 聚焦。

### M4 — 数据主权与工程清债（解 P1-2 / P1-4 / P1-5 / P1-6 / P2-x）

13. **导出 / 备份**：整库导出为 JSON（含资料、章节、chunk、概念、掌握度、试卷），支持导入还原——local-first 产品的信任底座。
14. **批量操作**：多选删除 / 打标 / 归属目标；导入前重名或内容 hash 提示。
15. **笔记与划线**：阅读页支持选中划线 + 笔记，落在章级，可被检索与出卷引用。
16. **切分参数可视化**：至少暴露「标题层级」「最小章长度」两个参数，配合预览。
17. **索引健壮性**：chunk 重建改为事务化（或先写后删），失败可回滚；设置页增加索引健康度（已索引 / 失败 / 待重建）。
18. **清债**：删除 `createKnowledgeEngine`、`renameChapter` 等无调用方实现；`DocumentStatus` / `rawSizeBytes` 要么真实赋值要么从类型移除。

## 5. 优先级建议

| 优先级 | 建议 | 理由 |
|---|---|---|
| 🔴 立刻做 | 15→3→5→4 | 出卷入口 + 卡片行动化 + 收敛宣称，都是小改动、直接改善"能不能用起来" |
| 🟠 本迭代 | 1→2→7→8 | 资料与目标的双向接线 + 测评接回资料，这是产品定位的兑现 |
| 🟡 下一迭代 | 9→10→11→13 | 概念层落库与图谱资产化，是把 MVP 推向 Phase 2 的地基 |
| 🟢 择机 | 6→12→14→16→17→18 | 体验与工程债，不阻塞闭环 |

> 一句话排期原则：**先把"资料 → 出卷 → 掌握度"这条最短闭环打通**，再去修图谱与存储的长尾。

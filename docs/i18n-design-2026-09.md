# 中英双语 i18n 设计方案（Personal Learning OS）

- 日期：2026-09-07
- 范围：前端（Tauri + React 19 + TS + Vite + Zustand），纯客户端，无构建期服务端依赖
- 状态：已实施（T1–T6 已于 2026-09-08 全部落地；自动化证据与人工走查见 `docs/i18n-walkthrough-2026-09.md`）

## 0. 结论与建议（先行）

| # | 决策点 | 结论 | 理由一句话 |
|---|---|---|---|
| D1 | 覆盖边界 | **UI 界面文案 + 引擎生成的提示文案（reason/feedback）** | 体验完整的双语；代码注释保持中文（开发者语言）、README 已双语、用户/种子数据不翻 |
| D2 | 技术路线 | **自研轻量 i18n（零新增依赖，类型安全）** | 仅 5 个 runtime 依赖的极简哲学；用「messages 对象即字典 + 函数叶子」天然类型安全，无需字符串 key/解析器 |
| D3 | 默认语言 | **跟随系统（auto）+ 手动覆盖**（三态 `auto/zh/en`） | 首次打开零配置；zh-* 系统显中文，其余显英文，设置页可覆盖 |
| D4 | 语言偏好存放 | **独立 store `useLangStore`（key `plos:lang:v1`）**，不并入 settings store | settings store 已被并发会话重构为 v2（active 复合结构 + 自定义 merge 白名单归一化），并入有丢字段风险且与 AI 模型配置正交 |
| D5 | 引擎文案改造方式 | 引擎函数**接收 messages 命名空间注入**（默认中文，UI 传当前语言） | 结构化重构（引擎只吐枚举+数据、UI 拼文案）改面大、Pre-MVP 不值；注入式改动小且切语言后 refresh 即重算 |
| D6 | 存量/种子数据 | **本期不翻译**（含 localStorage 存量 + loop.ts demo 种子），seed 本地化列为二期 | 内容语言与 UI 语言解耦是产品原则；已入库数据切语言不应被改写 |

**核心思路**：`i18n/` 一层薄抽象 —— `messages[lang]` 是**带类型的普通对象**（zh 为源、en 与 zh 同构类型），叶子是 `string | (params)=>string`；React 侧 `useI18n()` 返回当前语言 messages，**切语言 = 换对象 = 自动重渲染**。不需要字符串 key、不需要插值解析器、不需要复数规则引擎 —— 缺翻译在**编译期**报错，全链路类型安全。

## 1. 背景与目标

项目 README 定位 GitHub 开源、双语文档（README.md / README.zh-CN.md），但应用 UI 与引擎提示语目前**全部硬编码中文**。面向开源国际化与英文用户，需要：

1. 界面文案中英双语可切换，切换即时生效、无需刷新；
2. 默认跟随系统语言，中文系统进中文、英文系统进英文；
3. 引擎生成的学习建议/测评反馈文案随语言一致；
4. 不破坏既有的 local-first / 极简 / 类型安全工程约束。

**非目标**：代码注释翻译（保持中文开发者语言）；用户导入的资料、知识单元标题等**内容数据**翻译（语言属于"界面语言"，不属"内容语言"）；README/文档多语言维护流程。

## 2. 现状盘点：三层中文分布

全仓 59 个 ts/tsx 文件、40+ 文件含中文字符。按**性质**分三类，只有前两类进入 i18n 范围：

| 层 | 性质 | 代表 | 是否翻译 | 工作量 |
|---|---|---|---|---|
| L1 界面声明文案 | JSX 文本/aria/placeholder、⌘K 命令 label、导航 | AppShell 导航、HomePage（49 命中行）、ReviewSession（44）、GraphView 残留（43）、CommandPalette（43）、SettingsPage、AssessmentSession、CareerPage… | ✅ 是 | 中 |
| L2 共享标签表 | 枚举→中文映射（纯 UI 语义） | `features/units.ts`（kindLabel/actionKindLabel/goalTypeLabel/importanceLabel/UNIT_TITLES） | ✅ 是 | 小 |
| L3 引擎生成文案 | 逻辑层拼出面向用户的自然语言 | `learning-planner.ts`（40 命中行，reasons 模板串）、`assessment-engine.ts`（feedback："未作答。"/"主观题需 AI…"） | ✅ 是（D5 注入式） | 中 |
| — 注释 | 开发者语言 | domain/engine 全仓中文注释 | ❌ 否 | — |
| — 内容数据 | 持久化业务数据 | `loop.ts` `buildRagDemoDataset()`（goal.title="AI 应用工程师"、unit title/summary、doc title）、localStorage 存量、用户导入内容 | ❌ 否（D6） | — |
| — 抛错消息 | 运行时 Error | `throw new Error("未找到学习目标。")` | ⚠️ 开发者面可后置（本期跟随中文） | 极小 |

**关键约束发现（设计由此得出）**：

1. **`useSettingsStore` 已被并发会话重构为 v2**：`active: {source:"local"|"api",…}` 复合结构，`plos:settings:v1` key 不变、内部 schema v2，经自定义 `merge` 归一化（`normalizePersisted` 只挑**白名单字段**返回）。→ **若把语言偏好塞进该 store，必须同步改 SavedSettings/partialize/normalize 三处**，且未来字段增删都踩 merge 白名单坑。语言与 AI 模型配置正交，独立 store 是更安全的选择（D4）。
2. **路由已演进到 V2 章节目录**（`/knowledge` 已 301 到 `/learn`；ChapterCatalog/ChapterReader/Spaces 在册；GraphView/ImportModal 部分文件为历史残留或仍被引用）。→ 迁移清单以**当前路由可达页面**为准，实施前以 `git status` 复核。
3. **文案泄漏进逻辑层**：learning-planner/assessment-engine 直接拼中文自然语言字符串（且带插值：`目标「${goal.title}」所需（重要度：…）`）。这是全仓唯一的架构级障碍，不是简单"抽 key"能解决（D5）。
4. `index.html` 目前 `lang="en"` + 英文 meta（README 面向开源），但 UI 是中文 —— lang 属性与实际不符，需随语言同步。

## 3. 技术方案

### 3.1 总体架构

```
┌─ 组件层 ─────────────────────────────────────────────┐
│  const { m, lang } = useI18n();                       │
│  <span>{m.nav.home}</span>  ·  {m.study.items(n)}     │
└──────────────────────┬───────────────────────────────┘
                       │ messages 对象（当前语言）
┌──────────────────────▼───────────────────────────────┐
│ i18n/                                                 │
│  messages/zh.ts  源语言（唯一事实源，叶子=string|fn）│
│  messages/en.ts  与 zh 同构（TS 编译期校验对齐）      │
│  types.ts        Messages = typeof zh；Lang/Resolved  │
│  I18nProvider.tsx Context：resolve 语言→选 messages   │
│                   + 同步 <html lang> + document.title │
│  useI18n.ts      (lang, m, mode)                      │
│  detect.ts       系统语言探测（navigator.language）   │
└──────────────────────┬───────────────────────────────┘
                       │ mode: auto|zh|en（持久化）
┌──────────────────────▼───────────────────────────────┐
│ stores/useLangStore.ts   zustand persist plos:lang:v1 │
└──────────────────────────────────────────────────────┘
```

### 3.2 自研核心：messages 对象即字典（D2 落地）

**不引入 react-i18next / i18next / 语言检测器**。理由对比：

| 维度 | 自研（本项目选择） | react-i18next |
|---|---|---|
| 新增依赖 | **0** | i18next + react-i18next + i18next-browser-languagedetector（3 个） |
| 类型安全 | **编译期全检**：en 缺 key、key 拼错、参数签名错 → tsc 直接报错 | 字符串 key，需额外配类型 + ts 插件，常见做法仍不完整 |
| 插值/复数 | 函数叶子 `(n)=>…`，天然支持且类型约束参数 | 内建，需写格式串 |
| 体积 | ~150 行 | ~40KB+ |
| 命名空间 | 对象嵌套即命名空间 | 需配置 |
| 维护成本 | 双语字典人工维护，靠 tsc + 单测兜底 | 生态成熟、工具链全 |
| 适合 | 文案量 <1k 条、极简哲学、Pre-MVP | 大团队、内容运营、翻译工作流 |

**字典形态**（zh 为源，叶子 = 纯字符串 或 参数函数）：

```ts
// i18n/messages/zh.ts —— 唯一事实源
export const zh = {
  common: { save: "保存", cancel: "取消", back: "返回", confirm: "确认" },
  nav: { groupLearn: "学习闭环", home: "首页", study: "学习", settings: "设置" },
  units: { concept: "概念", skill: "技能", actionLearn: "学习", importanceHigh: "高" },
  engine: {
    goalRequired: (g: { title: string; importance: string }) => `目标「${g.title}」所需（重要度：${g.importance}）。`,
    notAnswered: "未作答。",
  },
} as const;
export type Messages = typeof zh;
```

```ts
// i18n/messages/en.ts —— 与 zh 同构：缺任何叶子 → tsc 编译错误
import type { Messages } from "./zh";
export const en: Messages = {
  common: { save: "Save", cancel: "Cancel", back: "Back", confirm: "Confirm" },
  nav: { groupLearn: "Learning loop", home: "Home", study: "Study", settings: "Settings" },
  units: { concept: "Concept", skill: "Skill", actionLearn: "Learn", importanceHigh: "High" },
  engine: {
    goalRequired: ({ title, importance }) => `Required for goal “${title}” (importance: ${importance}).`,
    notAnswered: "No answer.",
  },
};
```

**类型安全来源**：`en: Messages` 约束让缺漏在编译期暴露；组件里 `m.nav.home` 是属性访问而非字符串索引，无拼错空间。参数函数有显式签名，调用处 `m.study.items(count)` 参数类型受检。

### 3.3 Hook 与 Provider

```tsx
// i18n/useI18n.ts（概念）
interface I18nValue { lang: ResolvedLang; m: Messages; }
export function useI18n(): I18nValue;   // 读 Context，null 时兜底 zh
```

```tsx
// App.tsx —— 挂载在 HashRouter 内层即可（不依赖路由，放 main 也可）
<HashRouter>
  <I18nProvider>
    <Routes>…</Routes>
  </I18nProvider>
</HashRouter>
```

- `I18nProvider` 订阅 `useLangStore.getState().mode` → `resolve(mode)`：`auto` 时调 `detect()`，否则取 mode；把 `messages[resolved]` 放 Context。
- **副作用**：`useEffect` 同步 `document.documentElement.lang = resolved`；`document.title` 读 `m.appTitle`。
- 纯字符串叶子不做插值（需要时改成函数叶子即可，类型强制调用方更新）。

### 3.4 语言状态与持久化（D4）

```ts
// stores/useLangStore.ts
type LangMode = "auto" | "zh" | "en";
interface LangState { mode: LangMode; setMode: (m: LangMode) => void; }
// zustand persist, name: "plos:lang:v1", 无 merge/迁移（单字段，undefined→auto 由 DEFAULTS 兜底）
```

- **独立于 settings store** 的原因（D4 展开）：settings 现有自定义 merge 白名单归一化，加字段要动三处且易丢；语言与 AI 模型配置无耦合；单字段独立 store 零迁移成本。
- **切换即时生效**：`setMode` → persist + Provider 重选 messages → Context 变化 → 全树重渲染为另一语言（React 状态驱动，无刷新）。

### 3.5 引擎文案注入（D5）

改造原则：**引擎保持纯逻辑，文案参数化**，不把 domain 类型改造成结构化 reason。

```ts
// learning-planner.ts（改造后签名）
import type { Messages } from "../i18n/messages/zh";
import { zh } from "../i18n/messages/zh";

export function createLearningPlanner(m: Messages = zh) {
  return {
    buildPlan({ goal, graph, learnerState }) {
      // … 逻辑不变 …
      reasons.push(m.engine.goalRequired({ title: goal.title, importance: goal.importance }));
    },
  };
}
```

- **默认中文**：引擎侧单测/无 UI 调用场景行为不变（`= zh`）。
- **调用点传当前语言**：`runLearningLoop` 及 Home/Study 触发 refresh 的入口改为 `createLearningPlanner(useI18n 的 m)` —— 具体做法：把 i18n messages 从 store action 外层传入（loop 是纯函数，不直接读 React Context；由页面/⌘K 调 `refresh(langM)` 或 store 持有当前 m 引用）。
- **切语言后的旧快照**：LoopSnapshot 的 actions/reason 是字符串快照，切语言后由**下一次 `refresh()` 以新语言重算**（现架构每次刷新都重跑 `runLearningLoop`，天然支持）。ReviewSession/AssessmentSession 运行中的题面/feedback 以**会话开始时的语言**为准，不中途切换（可接受，会话短）。
- `assessment-engine` 的 feedback 字符串同理参数化。

### 3.6 内容/种子数据边界（D6）

- `buildRagDemoDataset()` 保持中文种子不动；`seedDemoIfEmpty` 逻辑不变。
- **二期候选**（写入 backlog）：seed 时按 `resolved lang` 取双语标题字典播种；存量 localStorage 数据永不动。
- UI 对用户数据的展示原则：**数据原文优先**（如 `goal.title` 显示用户存的字面量），只有**结构性 fallback**（`units.ts` 的 `kindLabel/importanceLabel` 等枚举标签、`unitTitle` 的 id fallback）走字典。

### 3.7 语言切换入口

- **设置页**新增「语言 / Language」区（三选：跟随系统 / 中文 / English）——与 AI 模型配置区并列。
- 壳层不动路由；⌘K 暂不加入语言命令（Pre-MVP 保持简单，见待定问题 Q2）。

## 6. 风险矩阵

| # | 风险 | 级别 | 缓解 |
|---|---|---|---|
| R1 | 英文文案普遍更长 → 侧边栏/按钮/徽章/图谱标签溢出 | P1 | CSS 弹性/省略号；双语走查矩阵逐页核对；关键位（导航/CTA/评级）优先人工目检 |
| R2 | 语言偏好误入 settings store 触发 merge 白名单丢字段 | P0 | 已决策独立 `useLangStore`（D4），规避 |
| R3 | 切语言后旧快照/已存文案仍是旧语言 | P2 | refresh 重算（现架构天然支持）；session 内以开始语言为准并文档化 |
| R4 | 内容数据与 UI 标签混用（如 unitTitle 的 id fallback）被误翻 | P2 | 原则固化：**数据原文优先，仅枚举/fallback 走字典**（3.6），代码评审检查点 |
| R5 | ⌘K 关键词过滤在切换语言后失效（中文关键词 vs 英文 label） | P2 | 过滤基于当前语言 label；双语同查列二期 |
| R6 | 并发会话持续改动同仓（settings/ai/src-tauri 等），迁移清单可能过期 | P1 | 实施前 `git status`/`git diff` 复核；小步提交（每 N 一 commit）；先删死代码再翻译 |
| R7 | 时间/相对日期格式化（“今天 HH:MM”）语言不一致 | P2 | 统一走 `Intl.DateTimeFormat(zh-CN/en-US)` 或字典模板，不散落硬编码 |
| R8 | 引擎参数化改动破坏既有单测（默认 zh 行为） | P2 | `= zh` 默认参兜底，存量单测不改即绿；新增 en 冒烟单测 |
